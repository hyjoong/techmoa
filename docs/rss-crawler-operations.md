# RSS 수집 실행과 결과 확인

피드 등록은 `scripts/rss/feeds.js`의 `RSS_FEEDS`를 사용한다. 먼저 미리보기로 범위와 신규 후보를 확인한 뒤 같은 옵션으로 실제 저장을 실행한다.

## 미리보기

```bash
pnpm crawl-rss --help
pnpm crawl-rss --dry-run --feed "NHN Cloud" --max-per-feed 20
pnpm crawl-rss --dry-run --feed "인프랩" --feed "한글과컴퓨터" --since 2026-09-01
```

미리보기는 RSS와 기존 DB를 읽어 중복·규칙 필터를 확인한다. **AI 호출, 글 저장, 제외 기록 저장, 모든 알림을 실행하지 않는다.** 썸네일을 위한 추가 웹 페이지 요청도 건너뛴다. 표시되는 신규 후보는 AI의 비기술 글 판정 전 최대 예상 저장 건수다.

`--help`와 잘못된 옵션 검사는 환경 설정이나 수집 서비스를 불러오기 전에 끝난다. 실제 미리보기에는 기존 글과 대조할 Supabase 설정이 필요하다. 환경 변수 값은 출력하지 않는다.

## 실제 저장

```bash
pnpm crawl-rss --feed "NHN Cloud" --max-per-feed 20 --no-notifications
pnpm crawl-rss --since 2026-09-01 --max-per-feed 20 --max-ai-articles 120 --no-notifications
```

`--dry-run`을 빼면 운영 DB에 저장한다. 알림을 원하지 않으면 `--no-notifications`를 함께 지정한다. 옵션 없는 기존 명령은 전체 피드 수집과 알림을 유지한다.

| 옵션                  | 의미                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| `--dry-run`           | DB 읽기와 RSS 확인만 수행                                                                      |
| `--feed NAME`         | 등록된 정확한 블로그 이름. 여러 번 지정 가능                                                   |
| `--since DATE`        | 해당 시각 이상인 글만 처리. 날짜만 쓰면 한국시간 00시, 시각을 쓰면 시간대가 있는 ISO 형식 필요 |
| `--max-per-feed N`    | 피드별 신규 분류 후보 상한. 기존 중복과 규칙 제외 글은 상한을 소모하지 않음                    |
| `--max-ai-articles N` | 전체 실행의 AI 분류 대상 글 상한. 내부 HTTP 재시도 횟수와는 별도                               |
| `--no-notifications`  | 개별 푸시·배치 푸시·Discord 모두 끄기                                                          |
| `--output PATH`       | 결과 JSON 경로. 기본값은 `rss-crawl-results.json`                                              |

건수는 양의 정수여야 한다. 상한을 생략하면 해당 제한을 적용하지 않는다. 날짜·건수·이름이 잘못되면 수집을 시작하지 않는다. 선택 범위 안에서는 최신 글부터 검토하며, 한도를 넘는 후보는 `deferred`로 기록한다.

AI 분류는 기존 요청 간 지연을 유지한다. `--max-ai-articles`는 글별 분류 시도 수를 제한하며, 한 글의 Fireworks 재시도는 추가 HTTP 요청을 발생시킬 수 있다. 미리보기에서도 같은 상한으로 후보를 계획하되 실제 AI 분류 건수는 0이다.

## 외부 요청과 태그 오류 처리

RSS 요청은 본문까지 읽은 후 XML을 파싱한다. 리다이렉트·HTTP 오류·시간 초과에서는 응답을 취소하고 정리한다. RSS와 썸네일 요청은 각각 본문 읽기를 포함해 10초 제한이며 리다이렉트는 최대 5회다. 썸네일 웹 요청은 중복·규칙 제외·기간·건수 제한과 AI 비기술 판정을 통과한 신규 저장 후보에만 수행한다. 썸네일 요청 실패는 기존 RSS 이미지로 대체하거나 이미지 없이 저장한다.

Fireworks 기본 모델은 `accounts/fireworks/models/gpt-oss-120b`다. 로컬 `FIREWORKS_MODEL` 또는 GitHub Repository variable `FIREWORKS_MODEL`로 재정의할 수 있다. 기본 모델은 2026-10-09에 [공식 서버리스 모델 페이지](https://fireworks.ai/models/fireworks/gpt-oss-120b)와 모델 목록 API에서 확인했다. 목록 조회는 추론 검증과 다르다.

AI 요청은 본문 읽기까지 30초로 제한한다. JSON 스키마와 허용 태그 목록을 공유하고, 정상 완료된 문자열 배열만 사용한다. 빈 본문·잘린 응답·잘못된 JSON은 오류로 기록하며 비기술 글로 제외하지 않는다. 정상 JSON `[]`만 비기술 판정으로 인정한다.

기본 실행은 AI 오류에도 기존 글 저장 정책을 유지한다. 저장된 글에 기본 카테고리 태그만 있거나 태그가 비어 있을 수 있으며 보고서에는 AI 오류와 실제 저장 건수를 함께 남긴다. 해당 글은 다음 수집에서 중복으로 처리되므로 태그 복구는 별도 백필이 필요하다. `scripts/backfill-tags.js`는 미리보기에서도 AI를 호출하므로 일반 RSS 미리보기와 구분한다.

배치 푸시의 Android 메시지 우선순위는 `normal`이다. 실행이 끝나면 해당 실행에서 사용한 Firebase 연결을 정리한다. Discord 요청과 응답 본문에는 15초 제한을 적용한다. 알림을 끄거나 미리보기일 때는 알림 모듈을 초기화하지 않는다.

2026-10-09 기준 우아한형제들 공식 `/feed/`와 동일한 글을 반환하는 `/?feed=rss2`는 로컬에서 200이지만 GitHub Actions에서 모두 403이었다. 등록 주소는 공식 `/feed/`를 유지한다. 해당 실행 환경에 대한 사이트 측 접근 허용을 확인해야 하며, 피드를 제거하거나 403을 성공으로 바꾸지 않는다. 이 오류가 남아 있으면 전체 실행은 다른 피드를 처리한 후 `partial_failure`와 종료 코드 1을 반환한다.

## 결과 파일과 종료 코드

시작·피드 완료·최종 결과를 JSON으로 저장한다. 같은 디렉터리의 임시 파일을 교체하는 방식으로 저장하며, 환경 설정 값은 로그와 보고서에서 가린다. 결과 파일에는 글 원문과 저장된 글 전체를 넣지 않는다.

- `schemaVersion: 1`: 결과 형식 버전
- `status`: `running`, `success`, `partial_failure`, `failed`
- `feedResults`: 피드별 성공 여부·처리/저장/중복/제외/보류 건수·시작/종료 시각·소요 시간·오류 단계와 메시지
- `totalCandidates`: 제한을 적용한 신규 분류 후보
- `totalDeferred`: 한도로 다음 실행에 남긴 후보
- `totalSkippedByDate`: 지정 시각보다 오래된 글
- `totalAiArticles`: 실제 AI 분류를 시도한 글 수
- `warnings`: 제외 기록 테이블 부재처럼 수집을 계속하면서 남긴 경고

새 글이 0개인 정상 피드와 파싱·분류·저장에 실패한 피드를 구분한다. 일반 실행은 실패한 피드를 기록하고 다음 피드를 계속 처리한다. 최종 결과에 실패가 있으면 종료 코드 1을 반환하며, 이미 성공한 피드의 저장 결과를 함께 남긴다. 옵션 오류는 종료 코드 2, 정상 완료는 0이다. 제한에 도달한 것은 실패가 아니며 보류 건수로 확인한다.

결과가 `running`에 머물면 실행이 아직 진행 중이거나 최종 기록 전에 중단된 상태다. 완료된 피드까지만 확정해서 판단한다. 강제 종료 시 진행 중인 피드의 AI 작업을 자동 재개하는 기능은 제공하지 않는다.

## GitHub Actions

기존 정기 실행 시각은 유지한다. 정기·푸시 실행은 `--max-ai-articles 120`을 적용하며 알림 동작은 유지한다. 한도로 남은 후보는 다음 실행에서 기존 DB와 다시 대조한다.

수동 실행은 미리보기와 알림 끄기가 기본값이다. 화면에서 블로그 이름·시작 날짜·피드별 상한·전체 AI 분류 상한을 지정할 수 있다. 실제 저장이 필요할 때만 미리보기를 해제한다.

성공·실패 모두 실행 요약과 `rss-crawl-results` 아티팩트를 남긴다. 커밋 댓글 대신 해당 실행의 Summary에서 확인한다. 초기 단계가 실패해 결과 파일이 없으면 성공 0건으로 표시하지 않고 결과 확인 불가로 안내한다.

## 제외 기록 테이블

`scripts/sql/excluded_articles.sql`은 수동 적용 SQL이다. 자동 마이그레이션이나 수집 옵션으로 테이블을 생성하지 않는다. 테이블이 없으면 보고서의 경고를 확인하고 Supabase SQL Editor에서 준비된 SQL을 적용한다.
